# Task contract: Issue #336 terminal response ownership

## Outcome

Every MCP client uses one bounded `review_start` contract, and `review_start` / `review_await` return the durable terminal product result without waiting for post-terminal cleanup.

## Owners and invariants

- `CodexReviewStore` owns terminal product state and the history terminal commit.
- The review worker owns cleanup completion and later developer diagnostics.
- MCP terminal readiness is `job.isTerminal && historyTerminalCommitIsResolved(jobID:)`.
- Worker/cleanup finality remains separate and continues to protect cleanup, deferred removal, and diagnostic mutation.
- A terminal core returned before cleanup must never change; a later cleanup failure may only add developer diagnostics visible through `review_read(logFilter: all)`.
- Result/history retention must remain valid while a result lease or worker owner exists.
- Actor-owned tasks keep explicit handles; no detached cleanup, sleeps, retry timing, or new mirror state.

## Scope

- `Sources/CodexReview/Store/CodexReviewStoreReviews.swift` and directly related Store tests.
- `Sources/CodexReviewMCPServer/CodexReviewMCPProtocolServer.swift`, protocol/server wiring, MCP docs, and directly related MCP tests.
- Delete the Claude/client-name/User-Agent bounded-start heuristic; all clients receive the configured bounded timeout.
- Keep the existing configured timeout value unless a failing contract test proves it is part of this issue.

## Non-goals

- Do not change MCP HTTP connection draining, runtime replacement, or the E2E `curl 18` fallback; those belong to dependent Issue #337.
- Do not change public review request/target shapes, persistence schema, UI rendering, Codex, or `openai/codex`.
- Do not make cleanup failure product-visible or mask the canonical terminal result.

## Required tests

- Generic/manual and Claude-like client metadata produce the same bounded `review_start` request.
- A running review still returns a running snapshot with `review_await` next action.
- After terminal history commit resolves, a held cleanup cannot block `review_start` or `review_await`.
- Releasing cleanup can append a developer diagnostic without changing the earlier terminal core.
- History removal/retention tests remain green.
